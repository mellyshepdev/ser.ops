Point it at your registry list. It SSHes into each server, scans ~/projects and ~/server (and their sub-directories) for every site, runs your tagger on the site directory, feeds the tag file into your ingestor, and pulls the finished search results back home. 3 to 9 servers, in parallel, unattended.

3–9 servers ssh + sftp paramiko only exit 1 on failure · CI friendly

04 — the contract
What autoweb.py expects from your tools
01

The registry list

One website per line. # starts a comment. A bare name is searched under your scan dirs (case-exact first, then case-insensitive); a line starting with / or ~ is used as a path as-is.

acme-corp  ·  beta-news  ·  /home/deploy/server/legacy-api
02

The tagger script

Invoked on every server as TAGGER_CMD <site_dir>. It must write the tag file (default .tags.json) inside the site directory. If it exits non-zero or the file is missing, the site is marked failed and the run keeps going.

python3 ~/tools/tagger.py /home/deploy/projects/acme-corp  →  .tags.json
03

The ingestor script

Invoked as INGESTOR_CMD <tag_file> — it receives the exact path the tagger just produced, and must write search_results.json into the same site directory. That file is your search result for the site.

python3 ~/tools/ingestor.py …/acme-corp/.tags.json  →  search_results.json
04

The harvest

Both artifacts are SFTP-pulled to ./results/<server>/<site>/, a full run_report.json (status, paths, timings, errors per site) is written, and the script exits 1 if any site failed — safe to run on a cron or in CI.

./results/srv-03/acme-corp/search_results.json  +  ./results/run_report.json
 usage — cli
$ python3 autoweb.py --registry registry.txt --config servers.json
$ python3 autoweb.py --servers srv-03,srv-05 --dry-run
$ python3 autoweb.py --workers 8 -v
# dry-run connects + locates every site first —
# always do one dry pass before a real one.
# one SSH session per server, sites run in order,
# servers run in parallel (ThreadPoolExecutor).
